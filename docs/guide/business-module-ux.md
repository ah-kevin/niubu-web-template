# 业务模块体验检查清单

在目标 app 内组合既有公共能力，一次完成一个业务模块的列表、详情和表单。先核接口与产品职责，再改呈现；不跨 app 导入业务源码，也不为普通模块新增一套资源框架。查询和提交接线遵循[表单与 CRUD](./forms-query-crud.md)、[鉴权与请求](./auth-request.md)，路由遵循[模块登记](./modules.md)。

## 列表与实体详情

- 名称、编码、类型等独立业务字段各占一列，树名称只承载名称、层级与展开。完整 ID 确有识别价值时用现有 Tooltip 的 hover/focus/触屏交互，不在普通行再放一层展开详情或要求操作者输入 UUID。
- 全局新增用于没有父对象的创建；行内“新增下级”明确带入该行父对象，合法类型和候选依当前权限及真实目录。编辑、状态和其它动作围绕同行对象，不从第一行或深度猜根节点，也不把组织节点 ID 当业务实体 ID。
- 需要独立返回、刷新和多实体切换的详情使用真实详情路由。实际 route/entity path 决定页签身份，`activePath` 只负责导航高亮；不要广泛放开隐藏路由来修顶部页签。
- 顶部名称与面包屑来自当前授权 owner、scope、generation 和实体 ID 匹配的已校验事实；不信任 URL 中的名称，不把业务 payload 或翻译后的标题塞进 PageTab/持久缓存。Breadcrumb 的可选 `label` 表达可信原文，缺省 `labelKey` 仍走翻译。
- 已打开详情的标题若依赖查询事实，订阅 QueryCache 不等于保活查询。按已打开/授权生命周期保留事实，关闭或 owner 退役时释放；复用原 query options，不覆盖 queryFn/meta、不为标题额外拉目录。读取失败不能继续冒用旧可信名称。
- 摘要紧凑呈现名称、编码和重要状态，返回在侧；长文本和窄屏正常换行，不隐藏业务信息。摘要、页签和内容保持连续，切页签仍针对同一个实体。

## 工具区与表格

- 模板表格默认表头与单元格居中；特殊列通过 `columnAlign` 单独覆盖，需要整表左/右对齐时显式传入 `align`。

- 无筛选表的真实工具可与业务页签并排；有筛选表把字段、查询、重置、新增和工具合成一条紧凑带。保持可见或完整 ARIA label，窄屏有序换行，表格可横滚但 body 不横溢，不加横滚常识教程。
- `DataTable.toolbar.render(node)` 只改变原 live toolbar 的渲染位置。用 React portal 放入当前页面自己的 commit-ref host，不复制 ColumnSettings/table 状态、不 imperative 搬 DOM、不在 render 向父组件注册 setState。host 未就绪可返回 null，owner/页签退休后旧工具也退出。
- `toolbar.title: null` 去除重复标题；全屏时工具留在表格内部，退出控制必须可达；外置与内部切换导致按钮重新挂载时，只交接本次丢失的按钮焦点，不抢占其他仍连接控件。列显隐、宽度、恢复默认和选择摘要始终连同一个 table 实例。
- 筛选输入是 draft，只有查询才应用。新增、刷新、设置不能隐式提交 draft；工具 host 优先放在 form 外，同 form 内的非提交按钮明确 `type="button"`。刷新沿已应用条件及原 signal/query key。
- 桌面默认应能看清常用列和操作；先用当前公共列宽合同合理分配，不以缩小字体、裁掉动作或全局样式覆盖来挤布局。

现成组合见 [TablesPage](../../apps/playground/src/examples/tables/TablesPage.tsx)；通用工具接线见 [TableToolbar](../../packages/effects/common-ui/src/data-table/TableToolbar.tsx)。具体产品的可写资格、父类型约束和 lookup 权限仍由 app 与后端共同决定。

## 普通表单与时间

- 编辑只开一层普通弹层；相关字段连续、紧凑，有空间才并列。用业务名称选择真实 lookup，明确加载、无权、失败、无候选和已停用状态；失败不退回任意 UUID 输入。
- quota、attributes、externalRefs 等技术 JSON 不因后端有字段就必须给普通运营编辑。隐藏时也从本模式的 schema、dirty review、可恢复草稿中排除，避免旧坏 JSON 阻塞正常保存。
- 不展示不等于清空数据：create 的默认值、update 的省略或保原值按真实接口合同处理；可选字段的 provided 语义、空数组与省略的区别都要核实。共享 DTO 出现部门、岗位等字段不代表当前产品端取得这些职责。
- 时间紧凑显示本地日期和时间，普通单元格不追加 IANA 后缀；墙钟输入按当前 display timezone 转换。先校验 ISO、offset 和 zone，零毫秒合法，非法值明确错误；未修改的原 instant、毫秒与长期值原样保留，不新造“长期”写入规则。
- 常识和实现保证不占主页面。编码规则、配额含义或代管影响等必要解释少量放字段 tips；加载、失败、缺权和校验错误仍短而明确，就地可见。

[FormsPage](../../apps/playground/src/examples/forms/FormsPage.tsx) 展示单 owner 与三种取消选择；[FeedbackPage](../../apps/playground/src/examples/components/FeedbackPage.tsx) 展示弹层与读取反馈。产品示例须适配本模块合同，不能把示例 DTO 当通用业务接口。

## 读取与操作生命周期

| 组合入口                                            | 使用约束                                                                                                      |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `Loading`（`@niubu/common-ui/read-state`）          | 局部四点状态区，有 busy/live 语义并支持 reduced motion；不负责发请求、延迟成功或伪造骨架。                    |
| `DataTable statePresentation="feedback"`            | 可选地把 pending/error 变为居中反馈，默认旧呈现不变。单 query 只有一块失败与唯一重试；重试 pending 撤旧错误。 |
| `ReadState actions`                                 | undefined 保原动作；显式 node/null 替代默认动作。嵌入表内不强塞返回工作空间，自定义说明不要逐字重复标题。     |
| `FormFrame allowDiscard` / `UnsavedGuard onDiscard` | 默认取消合同不变；按需提供继续编辑、保留过滤后草稿、明确放弃。关闭后恢复入口和恢复后输入焦点都要验证。        |
| `Modal size="wide"`                                 | 按内容选择宽弹层，受 viewport 约束；fullscreen 优先，默认尺寸与 Drawer 合同不变。                             |

- 来源空、筛选空、来源未知、当前页空、取消、无权和未读取分别表达；不把 pending 判空，不把 lookup 或写入的独立错误吞到主查询里。DataTable 非 ready 模型不能带 rows/已知计数，不用旧数据冒充新读取成功。
- layout、portal 和字段联动不能改变 owner/scope/generation、Abort、版本与幂等合同。每次 await 后核对当前操作；迟到的刷新不能关闭新编辑器，旧 owner 的结果不能写入新页面。
- 取消完成身份不能依赖会被 reset 改变的 operationKey/readiness。自有 reset 仍能关闭当前实例并清当前草稿，真正 owner 变更不能清新草稿；A→B→A 时旧通知永久退休。保持组件未卸载时，后续新输入仍能存草稿。
- 触发器仍连接且 owner/代次有效、用户没有转去另一个控件时才回焦；不要让旧操作抢新界面的焦点。

## 配置、权限与返回上下文

- 领域对象不一定有 `name`：字典类型、字典项和参数分别选择真实名称、标签或键作为编辑与确认对象，按当前语言取已校验记录，缺失时回退稳定编码。不要把资源名、`—` 或整个业务 JSON 当对象名称。
- 名称目录用完整业务组合键匹配，例如应用与模块共同识别模块；按原读取权限、owner 和 generation 隔离。未知、无权、失败与未读取保留可查编码，不用硬编码中文名称，也不把派生名称送进服务端排序或写入 DTO。
- 参数值按真实类型选择文本、数字、明确的是/否或 JSON 控件。`0`、`false`、显式 `null` 与未选分开；类型切换不悄悄改已有业务值，切回仍保留未改过的原输入。布尔控件要能表达未选，不能显示成 `false` 却要求先开再关才能提交。
- 权限选择优先按业务分类浏览，名称为主、编码可查询，明确已选数量与范围。切分类或搜索不清勾选；批选只影响当前合法候选，保隐藏项和未知已保存项。权限候选层级仍由领域适配器决定，公共选择器不猜授权资格。
- 返回列表可在同 owner 的页面内保存分页、排序和列设置等纯 UI 状态；旧业务实例仍正常卸载。不要为保表格状态而保活隐藏编辑器、Portal、确认窗口或旧写 owner，也不持久化 rows、记录和业务 payload。

## 长内容与恢复入口

- 桌面可对候选列表做有界内滚；手机优先一层主滚动，避免外层只露一小条候选区、滑动却被内层截走。底部动作始终可达；弹层内滚动高度需服从外框的高度预算，不能只按整个 viewport 计算。
- 不只检查 body 是否横向溢出：外框裁切也会藏掉超宽输入和按钮。文件控件、长格式说明与预览区显式允许收缩和断行；等数据就绪和入场动画稳定后，再核对真实控件边界及滚动。
- 每个独立查询失败后提供当前查询的重试，不能把窗口重新聚焦或给相同 query key 再赋一次值当恢复入口。重试 pending 撤旧错误，成功态的后台刷新保已知内容；重试仍即时核对 read owner、generation 和 signal，不重放写入。
- 输入验证要看提交后保留的控件值和实际查询结果；原生复合日期控件只改了 DOM 值，不代表应用收到变更。开发预览与源码不一致时先核当前输入和运行目录，再有依据地重载现有服务，不删测试缓存来制造通过结果。

## 逐模块收口

1. 先核列表、独立详情、页签、查询、新增、编辑、取消、状态与长内容是否符合当前产品职责；不要只看“能打开”。
2. 选择相称的组件/请求生命周期回归，真实检查桌面与窄屏、键盘、字段与同行动作；样式检查消费实际 CSS，不写 class 名镜像。
3. 区分源码判断、组件模拟请求、实际服务、受控示例与未验证分支；受控错误示范不等于历史服务故障已定位，文档描述当前实现而不是冒称历史冻结输入。
4. 保存可审差异与命令结果，按[工作方式](./workflow.md)验证；按用户本次明确的单模块或整批验收边界交付，不把工程通过当作人工验收。公共模板提供组合方式，不携带真实产品的授权规则或数据。
