# @niubu/core-design

Private workspace package with public source exports. No browser or IO dependency.

`defaultThemeProfile` contains the existing readonly light/dark semantic color
maps and shadow. `densityTokens` separately owns standard/compact dimensions.
`resolveTheme(profile, mode, brand = {})` returns a frozen, fresh semantic map;
it never sets density dimensions inline. Missing or invalid profile values use
the corresponding original defaults. Unknown keys are discarded.

`validateBrandOverride(unknown)` accepts only `--primary`,
`--primary-foreground`, `--ring`, and `--accent` with #RGB/#RGBA/#RRGGBB/#RRGGBBAA
values. Resolving a brand never mutates defaults or another result. Profile
colors use hex and shadows use 2–4 pixel lengths followed by hex; arbitrary CSS
cannot pass through the resolver.

`@niubu/styles` consumes these exports at build time to generate static CSS.
DOM application, system theme detection and persistence belong to effects.

Content design roles are generated by `resolvePresentationTheme`: semantic state
colors, tooltip/table/skeleton aliases, popup shadows, and fixed control metrics.
`densityTokens` additionally owns heading, caption, check/switch/badge/slider sizes
and popup padding. These are independent of root font size and are not new brand
override keys.

Primary text in dark content and dark focus rings use the light Ant palette's
index 3; pressed primary text and active navigation text use index 1 (light uses
index 6). The default dark values are `#52aeff` and `#a3daff`, respectively.
Explicit profile text and brand ring overrides retain their existing meaning.
Only default/custom content borders deepen to `#cdd0d6` / `#4a4a50`.
Sidebar, submenu and header text/borders retain their original region values,
including half-dark regions. Dark popup shadows use black in all regions.
Adding roles does not wire them into controls or change the Ant fill palette.
