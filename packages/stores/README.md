# @niubu/stores

Private workspace source exports. `createAppStores({ identityKey, readContext })` owns immutable session/workspace/UI/interaction snapshots, subscriptions and final disposal. That owner contains no business entity cache, persistence or authentication.

`StoresProvider` binds an explicit caller-owned instance and never disposes it during Provider replay. `InteractionProvider` remains the standalone form fixture owner and reuses the same interaction factory. Drafts use the original tuple identity, clone on write and stay only in memory until final disposal or refresh. The beforeunload listener exists only while mounted and dirty.

`createAuthSession<U, L>(options)` is a separate caller-owned auth session with `getSnapshot/subscribe`, `restore`, `login(input, returnTo)`, `logout`, `switchScope`, `refresh(signal)`, `markLoginExpired`, `requestContext`, and `dispose`. The root entry also exports `AuthSession`, `AuthSessionOptions` and `AuthSessionSnapshot`. Its adapter is the core `AuthAdapter<U, L, AbortSignal>`; neither the owner nor its snapshots contain credentials, storage or browser globals. React callers can bind `subscribe/getSnapshot` with their existing external-store binding.

Await `restore()` before creating identity owners. It returns only the authoritative user or null, publishes `loading` or `anonymous`, and does not load grants or reload. Then create app owners and call `switchScope(scope)`. Null means account scope; a concrete scope must match both kind and id in the restored user's workspaces. Codes and menus publish together, as owned deeply frozen copies. Loading, failure and expiry expose no grants and an aborted request-context signal; only ready grants enable a fresh request context.

Identity/scope transitions first revoke grants and advance generation, actively abort old operations and requests, then clean the captured immutable `AuthContext` (`identityKey`, `scope`, `generation`). `onScopeReset` must remove only that previous scope/generation's queries and extensions; it must not permanently dispose the reusable API client. `onIdentityReset` handles identity query cancellation, app-owned tab storage, all tabs including pinned tabs, and identity extensions; it must preserve persisted user preferences. Scope switches never reload. These callbacks may be asynchronous, so they must target the supplied context rather than reread current state.

Ordinary login and a different returned user id clean the previous identity and call the injected `reload`, without publishing the new user/grants to old owners. The app validates `returnTo` before passing it; an empty value uses `homeHref`. Only an expired login returning the same user id resumes the current scope in place. `loginExpired` stays true until new codes/menu are both ready. Input usernames do not determine identity.

`logout()` calls adapter `invalidateLocal()` synchronously, attempts remote logout and identity cleanup, then reloads `loginHref` even if either attempt fails. Failures remain in `snapshot.error` and reject the promise (multiple failures use `AggregateError`). Cookie adapters can return only `{ credentials: 'include' }`; their invalidation must prevent automatic restore even if remote cookie logout fails. Credential revocation and any local restore-blocked marker belong to the adapter.

Normal `refresh(signal)` is valid only while ready. It preserves generation, grants and the active request signal, with no reset or reload; the request client owns refresh single-flight coordination. A real refresh failure retains the user but marks login expired and revokes requests/grants. Cancellation rejects with `AbortError` and never marks expiry. Logout, relogin, scope change and disposal invalidate earlier operations even if network work ignores abort. Adapter restore/login/refresh must call `op.assertCurrent()` immediately before synchronous credential/storage commits. Disposed or superseded work cannot publish, reload or become current again.
